# Ingestion + Dual-Memory Improvement Plan — Meridian LLMOps

## 1. Current state

- **Pipeline orchestrates 4 stores inline:** `services/ingestion/pipeline.py:79-101` runs parse → chunk → `vector_store.index_chunks` → `graph_store.extract_and_store` → `storage.save_document` with no queue, no idempotency key, and hydrate-on-boot via `load_persisted_knowledge_base:33-61` re-extracting graph from full text on every restart.
- **Vector path mixes test stub with prod client:** `services/ingestion/vector_store.py:32-33` returns `tuple[float,...]` pseudo-embedding from `zlib.crc32` behind `lru_cache`, stored at `vector_store.py:150` as `vector=chunk.embedding`; `search:167-179` tries legacy `client.search` first and only then `query_points`, so 1.19 removal breaks the happy path before fallback runs.
- **Graph store is 265 lines of regex NER plus silent Neo4j bypass:** `services/ingestion/graph_store.py:76-121` keyword + capitalized-word extractor, `UNWIND` writes at `:137-166`, and `except Exception:167-168` logs a warning and keeps in-memory state, so Neo4j and memory silently diverge with no health signal.
- **Retrieval contract is add-only while deletes fan out manually:** `services/rag_engine/retrieval/hybrid.py:26-39` supports `update_chunks` append plus `add_chunks` but no remove; `services/rag_engine/app.py:604` (`clear_all`) and `:689` (`delete_document`) each call `retriever.update_chunks(vector_store.get_all_chunks())` after the fact, so BM25 holds stale chunks between delete and rebuild and graph/BM25/vector eviction lives in three places (`pipeline.py:111-126`, `vector_store.py:240-258`, `graph_store.py:173-204`, `bm25.py:19-63` has no delete).
- **Pins lag the 2026 stack:** `docker-compose.yml:5` pins `qdrant:v1.11.3`, `:21` pins `neo4j:5.18.0-community`, `pyproject.toml:15-16` floors `qdrant-client>=1.8.0, neo4j>=5.18.0`; `2026-09-28_TECH_TRENDS_CATCHUP.md:17-19` already flags `search/recommend` removal → `query_points`, RocksDB removal in 1.17 requiring stepwise upgrade, and lock-resolved driver 6.2.0 vs server 5.18 skew.

## 2. Confusion audit

Ingest-as-library-inside-engine means `IngestionPipeline` is constructed inside the RAG FastAPI process with no service boundary, so batch backfill, request-time ingest, and boot hydration share mutable `VectorStoreManager._memory_chunks` and `KnowledgeGraphStore.entities` with the query path — a slow PDF parse blocks retrieval. Dual-store writes are best-effort pairs: vector upsert succeeds, graph `UNWIND` warns-and-continues, disk save succeeds independently, leaving three truth sources with no transaction or reconciliation job. BM25 is an in-process `BM25Okapi` snapshot built at retriever construction and only appended via `add_chunks`; deletes and restarts never shrink it except through the full-rebuild trick in `app.py`, so keyword search returns ghosts. Silent fallback compounds this: `vector_store.py:156,207` and `graph_store.py:168,203` degrade to memory on any exception, and `is_fallback` is never surfaced to `/health` or logs at error level, so operators cannot tell which memory answered. Parsers (`parsers/__init__.py:25-45`) emit flat `## Page N` / `## Heading` markdown that the heading-only `chunker.py:24-45` splits on, discarding tables, code fences, and overlap guarantees — chunk quality, and therefore fusion quality, is accidental.

## 3. Simplified restructure

Proposed boundary: `ingest → chunk → embed → index (vector + graph + lexical) → evict`, each stage with one owner and typed handoff (`Document → list[Chunk] → list[EmbeddedChunk] → IndexReceipts → EvictionReceipt`).

- **Keep `IngestionPipeline` as thin coordinator**, move per-stage logic out: `parsers/` stays parse-only, `chunker.py` gains overlap + table/code awareness, new `embedder.py` isolates real embedder vs deterministic test stub (remove `lru_cache` tuple hack from `vector_store.py`), `index/` fan-out writes Qdrant + Neo4j + BM25 snapshot behind one `index_chunks` call.
- **Single eviction guarantee:** one `MemoryCoordinator.delete_document(doc_id)` that calls storage → vector → graph → lexical in order, returns per-store counts, and fails loudly if any store reports zero when storage reported one; `pipeline.delete_document` and both `app.py` delete endpoints delegate to it. `HybridRetriever` gains `remove_document(doc_id)` (rebuild BM25 slice or full rebuild under lock) instead of callers rebuilding from `get_all_chunks`.
- **Merge:** fold `vector_store.is_fallback` / `graph_store.is_fallback` into one `MemoryHealth` report consumed by readiness probe. **Split:** break `graph_store.py` (265 lines) into `extract.py` (regex/keyword today, pluggable NER later) and `neo4j_store.py` (driver, UNWIND, Cypher deletes). **Delete:** legacy `client.search` branch, `catalog` alias shim when frontend migrates, per-boot full graph re-extract (replace with persisted entity snapshot load).
- **Non-goals:** no new vector DB, no async queue/Celery, no LLM-based entity extraction, no Python base-image jump, no LangChain v1 agent rewrite.
