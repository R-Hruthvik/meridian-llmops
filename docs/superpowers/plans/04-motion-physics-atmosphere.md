# 04 — Motion, Physics & Atmospheric Background

Architectural blueprint for the three motion layers of the Meridian chat interface: atmospheric background, living fluid boundary membrane, and second-order component springs. Builds on `web/src/constants/springs.ts` (`MERIDIAN_SPRING`, `MERIDIAN_REDUCED_TRANSITION`, `useMeridianPhysics`) and the `FluidMembraneInput` / RagWorkspace dock pattern. Grounded in the local distilled KB (`04_motion.md`, `04_webgl_gpgpu.md`, `KB_TENETS.md`) and animations.dev / Devouring Details / Rauno / Codrops references.

## 1. Governing physics model

Every motion is a second-order spring, never a fixed-duration ease:

```
m·x'' + c·x' + k(x − xₜ) = 0
```

Derived quantities:

```
ωₙ = √(k / m)                         natural frequency (rad/s)
ζ   = c / (2·√(k·m))                   damping ratio
c   = 2·ζ·√(k·m)                       damping coefficient (derived)
ω_d = ωₙ·√(1 − ζ²)                     damped frequency (ζ < 1)
```

Reading ζ: ζ < 1 oscillates (slightly under critical = "premium/live"), ζ = 1 critical (fastest no-overshoot), ζ > 1 overdamped (slow, no overshoot). Settling is emergent: ≈ 4 / (ζ·ωₙ). Tenet 4: duration is emergent, never chosen.

Discrete integration (semi-implicit Euler, fixed dt = 1/60):

```
vₙ₊₁ = vₙ + ((−c·vₙ − k·xₙ) / m) · dt
xₙ₊₁ = xₙ + vₙ₊₁ · dt
```

Velocity transfer on gesture release (animations.dev): `v₀ = Δx / Δt` injected into initial conditions so a fast swipe keeps momentum.

Apple rubber-banding boundary (Devouring Details):

```
d_rubber = x · c_b / (x + c_b),   c_b = 0.55
```

As x → ∞, d → c_b; smooth, continuous, asymptotically bounded. Used when the membrane/capsule hits a container edge.

Reduced motion: `@media (prefers-reduced-motion: reduce)` → no rAF, single static frame, `MERIDIAN_REDUCED_TRANSITION` (0.1 s linear). Tenet: no-motion is the default, motion is the reward.

## 2. CSS spring definitions (per component)

Mass `m = 1` (normalized) throughout; `c` derived from `ζ` and `k`. Constants mirror the Devouring Details measured set in `04_motion.md` (§1) so the system feels consistent with the existing codebase.

| Component | k | ζ | c (derived) | ωₙ rad/s | settle ≈ | ω_d rad/s | overshoot | Character |
|---|---|---|---|---|---|---|---|---|
| Capsule vertical glide (42vh ↔ bottom dock) | 140 | 0.894 | 21 | 11.83 | 0.38 s | 5.30 | 0.19 % | near-critical, tiny overshoot |
| Left rail slide-in/out | 200 | 0.85 | 24 | 14.14 | 0.33 s | 7.45 | 1.6 % | crisp, visible overshoot |

```ts
  chatTurnReveal: { type: 'spring', stiffness: 400, damping: 31,  mass: 1 },
  buttonSnap:     { type: 'spring', stiffness: 500, damping: 40,  mass: 1 },
} as const;
```

Reduced-motion override: each maps to `MERIDIAN_REDUCED_TRANSITION` (`{ type: 'tween', duration: 0.1, ease: 'linear' }`).

### 2.1 Exact step response (source of truth for `linear()` tables)

Underdamped (ζ < 1):

```
x(t)/X = 1 − e^(−ζωₙ·t) · [ cos(ω_d·t) + (ζ / √(1 − ζ²)) · sin(ω_d·t) ]
```

Critically damped (ζ = 1):

```
x(t)/X = 1 − e^(−ωₙ·t) · (1 + ωₙ·t)
```

Overdamped (ζ > 1):

```
x(t)/X = 1 − e^(−ζωₙ·t) · [ cosh(ωₙ·√(ζ²−1)·t) + (ζ / √(ζ²−1)) · sinh(ωₙ·√(ζ²−1)·t) ]
```

### 2.2 `linear()` easing tables

`linear()` is generated by sampling the closed form at 60 Hz over `[0, 1.25 × settle]`, clamping the final stop to `1`, emitting `linear(y₀, y₁, …, y_N)`. Do not hand-author; regenerate at build. Devouring Details precedent: 92-stop tables (440 ms) and 91-stop `--timing-bounce`.

Exemplar — capsule glide (`k=140, ζ=0.894`, settle 0.38 s), 13 stops (~0.0315 s apart), sampled from the underdamped form, final clamped:

```css
--ease-capsule-glide: linear(
  0, 0.056, 0.178, 0.325, 0.466, 0.594, 0.700,
  0.784, 0.849, 0.898, 0.933, 0.958, 1
);
```

Usage with `transition`:

```css
.capsule {
  transition: transform var(--dur-capsule-glide) var(--ease-capsule-glide);
}
--dur-capsule-glide: 0.38s;   /* emergent; informational only */
```

For the remaining five components, substitute each row's `k, ζ` into the closed form and regenerate the stop list identically. Button snap and chat turn use fewer stops (shorter settle); modal uses critically damped form (no overshoot).

### 2.3 Theme transition variables

Global theme changes animate through CSS custom properties, never hard-coded hexes:

```css
:root {
  --theme-transition: --border, --background, --surface, --ink, --accent;
  --theme-duration: 350ms;
  --theme-ease: cubic-bezier(0.23, 0.88, 0.26, 0.92); /* Devouring Details --ease-swift */
}
* {
  transition: var(--theme-transition) var(--theme-duration) var(--theme-ease);
}
will-change: transform, opacity;   /* composited properties only */
[data-theme] { transition: none; } /* instant on theme root, children still ease */
@media (prefers-reduced-motion: reduce) {
  * { transition-duration: 0s !important; }
}
```

`transform` and `opacity` only for animated properties (GPU-composited, off main thread per animations.dev performance guidance).

## 3. Layer A — Atmospheric background

Decorative, fixed, `pointer-events: none`, `aria-hidden`. Renders below content.

### 3.1 Subtle coordinate grid

- Pitch: **24 px**, hairline **1 px**, color `rgba(var(--border) / 0.35)`.
- Corner crosses every **96 px** (4 grid cells): `+` marker, 1 px, same color/alpha.
- Implementation: CSS `repeating-linear-gradient` on both axes on a full-bleed layer; crosses via small positioned `::before/::after` or an SVG overlay. Single owner per edge (Tenet 2 — no double-border seams).

```css
.atmos-grid {
  position: fixed; inset: 0; z-index: 0; pointer-events: none;
  background-image:
    repeating-linear-gradient(0deg, transparent, transparent 23px, rgba(var(--border)/0.35) 24px),
    repeating-linear-gradient(90deg, transparent, transparent 23px, rgba(var(--border)/0.35) 24px);
  background-size: 24px 24px;
}
```

### 3.2 Procedural SVG noise grain

- `feTurbulence baseFrequency="0.75" type="fractalNoise" numOctaves="3"`, opacity **0.035**, `mix-blend-mode: overlay`.
- Kills plastic banding, adds tactile texture; static or very slowly drifting seed.
- Full-bleed fixed overlay, `pointer-events: none`, `aria-hidden`.

```svg
<svg xmlns="http://www.w3.org/2000/svg" width="0" height="0">
  <filter id="grain" x="-50%" y="-50%" width="200%" height="200%">
    <feTurbulence type="fractalNoise" baseFrequency="0.75" numOctaves="3" result="noise"/>
    <feComponentTransfer in="noise" result="alpha">
      <feFuncA type="table" tableValues="0 0.035"/>
    </feComponentTransfer>
  </filter>
</svg>
<div style="filter:url(#grain); opacity:0.035; mix-blend-mode:overlay; position:fixed; inset:0; pointer-events:none;"></div>
```

### 3.3 Interactive fluid pointer / vector lattice (N = 100)

Canvas 2D layer, fixed, `inset: 0`, DPR capped at 2, `aria-hidden`.

Field math (curl of a scalar potential, divergence-free — `div(curl(F)) = 0`, no sinks/sources):

```
ψ(x, y, t) = two-octave value noise, octaves scroll in opposite directions
v = ∇ × ψ = (∂ψ/∂y, −∂ψ/∂x)
```

- N = 100 nodes on a lattice + drifting particles; each advected: `p += v·dt`.
- Cursor reaction: within influence radius **R = 64 px** (Devouring Details pointer field, 48 px precedent; widened to 64 for this layer), displacement weighted by quadratic falloff `(1 − d/R)²`; outside radius = 0.
- Viscous decay: `v *= 0.92` per frame (field does not accelerate without bound; cf. Vanta standing-wave damping 0.985).
- Alpha **0.15–0.22**, soft additive draw (`globalCompositeOperation = 'screen'`-adjacent low alpha strokes).
- Cursor velocity injection: on `mousemove`, `v_cursor = Δp/Δt` biases local field (velocity transfer).
- Reduced motion: single static lattice frame, no loop, no listeners.

Rendering order per frame: clear → grid (CSS underlay) → grain (CSS overlay) → advect particles → draw particles (alpha 0.15–0.22) → composite.

## 4. Layer B — Living fluid boundary membrane

Owned by `FluidMembraneInput` (RagWorkspace): hero center when empty, springs to bottom dock once a conversation starts. The membrane is the capsule perimeter contour.

### 4.1 Persistent rAF loop

- Runs at display refresh; **does not terminate on arrival**.
- Kill switches: `prefers-reduced-motion: reduce`, `document.hidden` (Page Visibility API), battery-saver / low-power mode.
- Delta-time compensated accumulator; fixed sub-step for physics, variable for render.

### 4.2 Dual-octave traveling harmonic sine contour

Capsule perimeter parameterized by arc length `s ∈ [0, L)`:

```
r(s, t) = R + A₁·sin(k₁·s − ω₁·t + φ₁) + A₂·sin(k₂·s − ω₂·t + φ₂)
```

- `A₁ = 2.5 px`, `A₂ = 1.2 px` (dual octave: `k₂ = 2·k₁`, `λ₂ = λ₁/2`).
- `ω₁ ≠ ω₂` (different travel speeds) → beating/interference = living, non-repeating membrane.
- Two octaves traveling in opposite directions produce turbulence rather than drift (cf. WebGL two-octave Perlin, `04_webgl_gpgpu.md` §3).

### 4.3 Bilateral acoustic typing ripples

On each keystroke at perimeter point `s₀`, time `t₀`:

```
ripple(s, t) = B · exp(−(s − s₀ − v·(t − t₀))² / (2σ²)) · exp(−(t − t₀) / τ)
```

- Radiates **both directions** (±v) along the perimeter from `s₀`.
- `B ≈ 1.5 px` amplitude, `τ ≈ 350 ms` decay, `v ≈ 60 px/s` along perimeter, `σ ≈ 12 px` width.
- Additive with the sine contour; result clamped to bleed bounds; decays smoothly (non-linear decay exponent > 1 avoids mid-amplitude mush, cf. Codrops ghost-stack `(1 − age/5)^1.35`).

### 4.4 Magnetic cursor pull

For each membrane sample point, distance `d` to cursor:

```
F = F_max · (1 − d / 64)²  toward cursor,   d < 64 px
F = 0,                       d ≥ 64 px
```

Quadratic falloff within **64 px** (soft field — square falloff reads physical, linear reads mechanical, per Devouring Details pointer field). Added to point velocity, then viscous decay.

### 4.5 Canvas bleed padding

Canvas sized `capsule bounds + 32 px` on all sides. Waves clipped to the capsule path via `ctx.save(); ctx.clip(capsulePath); …; ctx.restore();`. The **32 px** bleed prevents wave clipping at the capsule edges.

## 5. Rendering pipelines

### 5.1 Canvas 2D pipeline (primary, all three layers)

Per rAF frame:

1. **Resize:** backing size = `ceil(cssSize · dpr)`, dpr capped at 2.
2. **Clear:** transparent (grid + grain are CSS layers).
3. **Particles (N = 100):** advect through curl field, apply cursor force + viscous decay, draw strokes alpha 0.15–0.22, batch into one path per alpha tier.
4. **Membrane:** integrate sine contour + typing ripples + cursor pull with viscous damping; build `Path2D`; `clip` to capsule; stroke `rgba(var(--ink) / 0.35)` 1 px.
5. **Composite:** draw to screen.

No read/write same texture; every layer draws from computed state, never from the previous frame's pixels (avoid feedback artifacts except the optional grain).

### 5.2 WebGL pipeline (optional high-end tier)

Only if Layer A/B exceed Canvas 2D budget. Ping-pong FBO (`04_webgl_gpgpu.md` §1):

- State texture `RGBA` float: `.rgb` = position, `.a` = life (halves buffers).
- Curl noise from two-octave Perlin scrolling opposite directions; aspect-correct radial falloff `uv.x *= res.x / res.y`.
- Kawase bloom (4-tap diagonal kernel, chained offsets) for glow; `gl_Position = (x, y, 1, 1)` so bloom never depth-tests.
- Membrane as fragment SDF + sine contour; mouse → specular direction and → mask (couple material to input, Tenet: couples scene to input so it feels alive).

Fallback rule: if WebGL unavailable → Canvas 2D; if reduced motion → static.

## 7. Accessibility & performance constraints

- `prefers-reduced-motion: reduce` → static single frame, no rAF, no pointer listeners, `MERIDIAN_REDUCED_TRANSITION` everywhere.
- Decorative canvas: `aria-hidden="true"`, `pointer-events: none`, no focusable children.
- Particle count scales: N = 100 desktop, N = 40 mobile (main thread is a budget, Tenet 6).
- `transform`/`opacity` only for animated properties; `will-change` limited to composited properties.
- Canvas DPR cap 2; sleep on hidden tab; resume on `visibilitychange`.

## 8. Approaches considered

| Approach | Tradeoff | Decision |
|---|---|---|
| Fixed-duration CSS `ease` for all motion | Simple but interrupting mid-flight restarts from zero (jank); duration is guessed, not emergent | Rejected (Tenet 4) |
| WebGL for all atmospheric layers | GPU-powerful but higher complexity, fallback burden, overkill for N=100 | Rejected for primary; optional tier |
| Canvas 2D + CSS grid/grain (this spec) | Low dependency, CPU-affordable at N=100, matches existing `FluidMembraneInput`, degrades gracefully | **Selected** |
| Spring per component vs one global spring | Global spring (MERIDIAN_SPRING ζ=1) too sluggish for button snaps, too stiff for rail | Per-component k/ζ (this spec) |

## 10. Risks / open questions

- `linear()` stop tables are generated from the closed form; one full exemplar given, remaining five regenerate identically — verify stop count vs settle for short springs (button snap 0.20 s) so tables aren't under-sampled.
- Canvas 2D membrane + particles at N=100 on low-end mobile may approach the main-thread budget; if so, drop to N=40 or promote membrane to a static CSS sine with JS only for ripples.
- WebGL tier is unspecified in detail (shaders not written); only adopt if Canvas 2D profiling shows missed frames.

Skipped: implementation of individual React components and WebGL shaders (separate tasks). Not verified against a running build (no test run performed).
